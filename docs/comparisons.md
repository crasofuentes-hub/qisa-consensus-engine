# Comparisons (Reproducible): QISA vs Baselines

This document frames **reproducible, artifact-backed comparisons** between QISA and simple baselines.
It is intentionally scoped to what can be verified from this repository: deterministic runs, trace verification, and pinned benchmark artifacts.

## What is being compared
All methods here operate on the same benchmark scenario inputs and are evaluated on:
- **converged**: reached stability within max steps
- **steps**: number of iterations
- **final_state**: terminal state (JSON)
- **records**: trace length
- **trace_hash**: final hash of the trace chain (audit signal)

The canonical pinned artifact is:
- `bench/results_scenario_v1.json` (validated by `tests/test_bench_artifact.py`)

The comparison table is generated by:
- `python -m bench.make_results_table`

## Baselines (implemented)
These baselines are intentionally simple and deterministic, representing common aggregation shortcuts:

- **single**: one perspective decides (no aggregation)
- **weighted_avg**: weighted average of numeric opinions (continuous aggregation)
- **majority_binned**: bin opinions and take majority vote (discrete aggregation)

QISA differs by treating aggregation as a **fixpoint process** with **audit-grade trace semantics**.

## Failure cases to watch
Even when `converged=True`, simple aggregators can fail in ways that matter in audited systems:

1. **Tie instability (discrete voting)**
   - Majority-style methods can be sensitive to binning, ties, and ordering choices.

2. **Averaging hides disagreement (continuous averaging)**
   - Weighted averages may “smooth out” incompatible positions and produce values that no perspective endorsed.

3. **Non-convergence under adversarial operators**
   - Any iterative method can oscillate if the operator is not contractive / stabilizing.
   - QISA makes this explicit via max-steps bounds and trace evidence; future scenarios will cover adversarial disagreement.

## Where QISA is structurally different
This is the core claim: QISA is not just “another aggregator”. It is an **auditable computation model** for consensus.

### 1) Fixpoint semantics (convergence + idempotence as first-class)
- QISA runs consensus as a bounded fixpoint iteration.
- Once converged, re-running from the converged state should return the same output.
- Evidence:
  - `tests/test_convergence.py`
  - `tests/test_idempotence.py`

### 2) Tamper-evident trace chain (audit primitive)
- Each step record participates in a hash chain.
- Any modification of a step breaks verification.
- Evidence:
  - `src/qisa/traces.py`
  - `tests/test_trace_hash.py`

### 3) Verifiable export (audit workflows)
- Traces can be exported as JSON and verified offline.
- Evidence:
  - `examples/audit_demo.py`
  - `tests/test_trace_verify.py`

### 4) Artifact-backed benchmarking (reproducibility discipline)
- Results are pinned in-repo and validated by tests.
- Tables are generated from artifacts, not hand-written claims.
- Evidence:
  - `bench/results_scenario_v1.json`
  - `tests/test_bench_artifact.py`

## Summary
If you only need a quick numeric aggregation, baselines may suffice.
If you need **auditability**, **deterministic replay**, and **tamper-evident execution evidence**, QISA provides a structurally different foundation.
